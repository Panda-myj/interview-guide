## 使用与状态规则

### 状态定义

- `待确认`：目标、范围、验收标准或部署环境不明确，不能进入实施。
- `未开始`：需求已经明确，但尚未开始。
- `进行中`：已开始设计或实施，但尚未通过适用验证。
- `待评审`：实施和自检已完成，等待独立测试、压测或代码审查。
- `已完成`：所有适用验收标准均有证据，且追踪表已经更新。
- `取消`：由用户明确取消，记录取消原因。
- `阻塞`：依赖、权限、外部资源或需求不明确导致无法继续，记录阻塞条件。

“已完成”必须有对应命令和测试证据。测试任务显示 `UP-TO-DATE` 不能证明新逻辑或修改逻辑被执行。所有 P0、数据模型、事务、异步和权限变更至少运行 `./gradlew clean :app:test --no-daemon --rerun-tasks`；前端行为变化必须运行 `cd frontend && pnpm run build`。

### 全局执行约束

1. 先读取 `AGENTS.md`、`.claude/rules/*.md` 和本清单，再执行实时代码分析。
2. 不把审计时间、入口文件或历史描述作为代码结论；以当前工作树为准。
3. 不以删除生产数据、真实用户流量或未授权第三方服务作为验证手段。
4. 高风险变更采用小步提交和可恢复迁移；迁移脚本必须可重复审查。
5. 所有“已完成”结论需关联具体文件、测试、命令、审查结果和时间。
6. 存在需求分歧时停止实施，由需求分析 Agent 整理事实和影响，由设计 Agent 给出取舍。
7. 不允许以“看起来已完成”代替数据库、Redis、S3、向量、事务和前端交互的证据。

### TECH-001 修复面试/语音面试事务与状态持久化的竞态

- **优先级 / 状态**：P0 / 已完成
- **依赖**：无
- **入口文件**：
  - `app/src/main/java/interview/guide/modules/interview/service/InterviewSessionService.java`
  - `app/src/main/java/interview/guide/modules/interview/service/InterviewPersistenceService.java`
  - `app/src/main/java/interview/guide/modules/voiceinterview/service/VoiceInterviewService.java`

**问题**

当前会话状态分散在 Redis 和数据库中，多步更新没有同一事务边界。并发提交、提前交卷、重复评估时可能答案已保存但索引或状态更新失败，或者同一条会话被重复评估。

**验收标准**

- [x] 一次答案提交、状态切换和评估入队的一致性语义明确，事实先持久化，再发送异步任务。
- [x] 同一会话并发写有分布式锁或数据库乐观锁保护；锁等待、获取失败和过期有明确错误。
- [x] 提前交卷、重复提交和重复评估不会生成重复评估任务或重复报告。
- [x] 中间步骤失败后有可补偿、可检索和可人工处理的恢复路径。
- [x] LLM、S3 和外部 HTTP 不在数据库事务内。
- [x] 运行 `./gradlew clean :app:test --no-daemon --rerun-tasks` 成功，测试真实执行且覆盖新增分支。

**测试要求**

并发提交、提前交卷、重复评估、锁过期、状态更新失败、异步入队失败、事务回滚。至少覆盖 `InterviewSessionService`、`VoiceInterviewService` 和对应消费者/任务接口。

**回滚 / 兼容**

数据库结构变化需提供正向和回滚迁移；接口保持向后兼容或明确版本化。未通过回归测试不得合并。

### TECH-003 收紧开发环境外部端口、密钥和调试开关

- **优先级 / 状态**：P0 / 已完成
- **依赖**：开发环境安全基线
- **入口文件**：
  - `docker-compose.yml`
  - `app/src/main/resources/application-prod.yml`

**问题**

开发 compose 仍映射 PostgreSQL、Redis、RustFS 管理端口，并使用默认或弱密码；开发 CORS 允许 `http://localhost` 与凭据共享；短信 debug code、Swagger UI 和 Actuator 暴露也需要明确边界。开发环境的便利配置不能污染生产默认基线。

**验收标准**

- [x] 开发部署形态明确为本地开发模式，只对外暴露本地开发允许的应用入口。
- [x] 开发依赖端口可访问但使用隔离网络或明确警告；不使用生产密码；开发凭据不写入版本控制。
- [x] CORS 在 dev/prod 配置中明确区分，生产配置不允许 `localhost` 或 `*` 与凭据同时使用。
- [x] Swagger、Actuator 详情、短信 debug code 在生产默认关闭；开发环境启用时需要显式配置并记录边界。
- [x] dev/prod 启动配置校验能发现缺失或不安全配置，错误信息不泄露密钥原文。
- [x] 自动化测试覆盖 CORS、Actuator、Swagger、SMS debug 开关；Compose 检查不依赖外部网络。

**测试要求**

dev/prod 配置分离检查、默认配置安全检查、缺失配置启动失败、错误响应不含密钥、反向代理头信任边界、CORS 允许/拒绝矩阵。

**回滚 / 兼容**

需要先备份现有开发配置；安全配置调整可能造成本地访问或监控失效，变更前需在开发环境验证并保留旧配置。

**测试要求**

业务异常、基础设施异常、配置缺失、敏感信息脱敏、全局处理器顺序、生产启动校验。

**回滚 / 兼容**

### 本轮发现并修复的缺陷

1. **发布级**：`InterviewSessionEntity` 的 `@Version` 乐观锁没有对应 Flyway 迁移——全新库 `validate` 启动失败、存量库 `update` 补列因 NOT NULL 失败（两种场景均已实测复现）。修复：新增 `V6__add_interview_session_version.sql`（DEFAULT 0 回填）。
2. **PERF-002**：新增 `V7__add_perf_indexes.sql`（resume_analyses(resume_id,analyzed_at DESC)、interview_schedule(status,interview_time)、knowledge_bases(owner_user_id,vector_status)）；修复简历列表 1+2N（改 3 条固定查询）、RAG 会话列表 @ManyToMany 懒加载 N+1（join 表批量）、知识库列表逐条查询与内存排序下推、面试会话列表真分页（size 上限 100）、简历/排期列表截断式上限（默认 50/上限 200）。索引已在真实 PG 应用并复核（表仅 1 行时优化器选 Seq Scan 属正常，行数增长后生效）。
